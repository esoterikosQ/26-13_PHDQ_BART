# 더 큰 모델로 한국어 GEC 파인튜닝 비교 결과

2026-09-29 · `plan2.md`의 후속 실험 결과. KoBART(124M)를 기준으로, 같은 데이터와 평가로 더 큰 모델 4개를 파인튜닝해 비교했다. 시간순 작업 기록은 `log.md`(2026-09-26 20:24 이후), 계획과 근거는 `plan2.md`, 선행 재현 결과는 `result_kobart.md`에 있다.

## 1. 요약

- **최고 성능은 pko-t5-large(821M)다.** 시나리오 1 테스트 GLEU(3-seed 평균)가 korean_learner 59.19, lang8 39.84, union 49.16으로 가장 높다. native에서는 kanana-1.5-2.1b가 82.96으로 근소하게 앞선다(+0.26).
- **2.5배 큰 LLM(kanana-1.5-2.1b, 전체 파인튜닝)은 pko-t5-large를 넘지 못했다.** korean_learner·lang8·union에서 0.5–0.7점 낮고, 추론은 약 4배 느리다. 재현율은 대체로 가장 높지만 잡음이 많은 lang8·union에서 정밀도가 3.5점 정도 낮다. 우려했던 심한 과교정이나 형식 이탈(설명문·빈 출력)은 없었다(이탈 0건).
- **모델 계열(사전학습 언어·토크나이저) 효과가 크기 효과보다 크다.** KoBART → pko-t5-base(2.2배)가 +2.3~+5.0점인 반면, 같은 BART 계열의 다국어 mBART-50(4.9배)은 KoBART와 거의 같다.
- **같은 계열 안의 순수 크기 효과는 약 2점이다.** pko-t5 base → large: korean_learner +1.7, lang8 +1.9, union +2.0. 모든 모델이 포화된 native에서는 +0.3.
- **새 표준 학습 코드(gec2)의 KoBART가 논문 recipe로 재현한 KoBART보다 6.0–10.3점 높다(테스트 GLEU, korean_learner +6.8, native +10.3, lang8 +6.0, union +9.7).** 비교는 같은 코드로 학습한 KoBART(gec2)를 기준으로 했다.
- **seed 간 흔들림이 작다(테스트 GLEU ±0.04–0.33).** 재현 KoBART의 seed 간 범위(0.6–2.5)보다 훨씬 작아, 모델 간 0.5점 이상의 차이는 안정적이다. 같은 seed·GPU 구성으로 두 번 돌린 run은 epoch별 검증 GLEU까지 똑같았다.
- **논문과의 일치**: 오류 유형별 점수 계산을 재구성해 재현 KoBART로 논문 Table D.4와 맞췄다(유형별 GLEU 차이 평균 0.84, 전체 차이 +1.05와 같은 크기). 시나리오 2(union 선학습)의 "정밀도↑·재현율↓" 경향은 재현 KoBART에서는 나타나지만 gec2 모델들에서는 거의 사라진다(§5).

**공통 조건** (`plan2.md` §1, §3)

- **데이터**: `data/Preprocessed/<data>/<data>_{train,val,test}.txt`, 4개 데이터셋(korean_learner, native, lang8, union).
- **평가**: 원문 기준 GLEU(source·reference는 데이터 원문, hypothesis만 모델 출력), 공식 `<data>_test.m2`로 M² P/R/F0.5. 새 평가로 재현 KoBART 21 run을 다시 채점해 기존 수치와 완전히 같음을 확인했다.
- **학습 코드**: `gec2/`. HF 표준 방식(실제 pad, attention mask, 라벨 −100, 모델 내부 shift)을 쓰고, 학습 전 누설 검사와 첫 배치 학습 모드 검사를 한다.
- **학습 설정**: torch AdamW(bias 보정), weight decay 0.01, clip 1.0, warmup 10% + cosine(10 epoch 예정 step), bf16-mixed, 전역 batch 64(micro × GPU × accumulation). seq2seq는 dropout 0.1, LLM은 기본값(attention dropout 0.0).
- **생성**: 빔 4, 샘플링 없음, 최대 생성 길이 `min(512, ceil(2 × batch 최장 입력) + 10)`.
- **LLM 프롬프트**: `다음 문장의 문법 오류를 고치세요.\n입력: {src}\n출력: `이며, 손실은 출력 부분에만 건다. 출력은 첫 줄만 쓴다.
- **체크포인트 선택**: 검증 GLEU 최고 epoch로 테스트한다. **트랙별 규칙 차이**: seq2seq는 10 epoch 고정, LLM은 최대 10 epoch에 조기 종료(min_delta 0.2, patience 3, 4 epoch 이후)를 쓴다.
- **lr 탐색**: korean_learner seed 0에서 후보당 3개 값을 돌려 검증 GLEU로 골랐다. KoBART(gec2) 5e-5, pko-t5-base 5e-4, mBART-50 3e-5, pko-t5-large 1e-4, kanana 1e-5다. KoBART·pko-t5-base는 범위 위쪽 끝, pko-t5-large·kanana는 아래쪽 끝이 선택됐다.
- **시나리오 2 (union → 개별)**: 같은 seed의 union 최고 체크포인트에서 가중치만 가져와 새로 학습하고, 시작 lr은 union lr의 1/3이다.
- **seed**: 0, 1, 2. 모든 모델 × 데이터셋 × 시나리오 조합에서 3개 seed를 모두 돌렸다(누락 없음).

- **일치하는 점**: native에서 시나리오 2가 GLEU를 낮추는 방향은 모든 모델에서 같다. 다만 폭은 논문(−7.5)보다 훨씬 작다(−0.5 ~ −2.5).
- **다른 점**: 논문의 "정밀도가 크게 오르고 재현율이 내려간다"는 경향은 원본 recipe로 재현한 KoBART에서는 다시 나타난다. 하지만 표준 학습(gec2)에서는 korean_learner·native에서 거의 사라진다. 이 경향의 상당 부분은 원본 학습 방식의 특성으로 보인다. lang8에서는 gec2 모델들의 정밀도와 재현율이 **둘 다** 올라 F0.5가 +2~+5.4 오른다. lang8 시나리오 2는 모든 모델에서 최고 검증 epoch가 0–1로 빨랐다(union 학습에 lang8 학습셋이 포함됨).

**오류 유형별 점수 (논문 Table 7 / D.4)**

- **계산 방식 재구성**: 논문과 저자 코드 모두 유형별 계산 방식을 적지 않았다. 그래서 "그 유형의 정답 편집이 하나 이상 있는 테스트 문장만 골라 GLEU·M²를 계산"하는 방식으로 재구성했다(`gec2/errtype.py`). 근거는 두 가지다. Table D.4에서 편집이 0개인 유형이 P/R/F0.5 100·GLEU 0으로 나오고(m2scorer에 빈 집합을 넣은 값), 정답 M²의 유형별 편집 수가 논문 Table D.3의 테스트 개수와 정확히 일치한다.
- **검증**: 재현 KoBART(union, 3 seed)로 계산한 값을 논문 KoBART Kor-Union 행과 비교했다. 유형별 차이는 GLEU 평균 0.84(최대 2.47), P 0.89, R 1.32, F0.5 1.26이다. 이는 전체 점수 차이(34.75 vs 33.70, +1.05)와 같은 크기이고, 유형 간 높고 낮은 순서도 같다.

| KoBART(gec2) | 1138 | 1105 | 1192 | 1184 | **1177** | 2.0GB |
| pko-t5-base | 384 | 393 | 451 | 434 | **432** | 4.3GB |
| mBART-50 | 305 | 306 | 347 | 337 | **335** | 6.8GB |
| pko-t5-large | 184 | 196 | 225 | 214 | **213** | 10.7GB |
| kanana-1.5-2.1b | 42 | 31 | 59 | 58 | **54** | 29.2GB |

- **해석 범위**: 이 값은 **이 환경(GPU·batch 64)에서의 처리량**이다. 절대 배율은 GPU와 batch에 따라 달라지고, 작은 모델은 더 큰 batch를 쓸 여지가 있지만 반영하지 않았다. 순서와 대략적인 크기(수 배 ~ 수십 배)만 해석한다. 토큰 하나당 계산량 차이가 근본 원인이라 순서는 GPU가 바뀌어도 유지될 것으로 본다.
- **다른 GPU 참고값**: kanana korean_learner 테스트 속도는 Neuron A100 × 2에서 약 58, H200 × 1에서 약 64문장/초였다(학습 run의 테스트 단계 기록).
- **kanana의 데이터셋별 편차**(native 31 vs lang8 59): 가장 긴 입력 batch 하나가 약 20초로 고정 비용이 크기 때문이다. LLM의 최대 생성 길이가 프롬프트를 포함한 입력 길이 기준이라, seq2seq보다 상한이 넉넉하다. 출력이 실제로 길어진 경우는 없었다.
- **논문 수치(KoBART 38.25문장/초, V100)**: GPU와 batch가 달라 절대값을 비교할 수 없다.

**학습 시간** (run당 학습 + 매 epoch 검증 생성, 3-seed 평균)

seq2seq는 10 epoch 고정이고, kanana는 조기 종료로 멈춘 epoch 수를 괄호에 적었다. H200 1장이 A100 2장보다 epoch당 약 25% 빨랐다.

## 7. 한계와 주의

- **seed 0 lr 탐색**: lr은 korean_learner seed 0 한 번으로 정했다. 선택된 lr이 탐색 범위 끝에 있는 모델이 4개라, 범위 밖에 더 좋은 lr이 있을 수 있다. 모든 모델에 같은 탐색 예산(3개 값)을 준 것은 지켰다.
- **트랙별 규칙 차이**: seq2seq는 10 epoch 고정, LLM은 조기 종료다. kanana lang8·union은 1–2 epoch에서 최고점이 나와 조기 종료가 결과에 영향을 주지 않았다.
- **단일 참조 정답**: 정답이 문장당 하나다. korean_learner 테스트에서 4개 seq2seq 모델이 같은 출력을 냈는데 정답과 다른 문장이 9.2%였고, 그중에는 문체 교체나 비문인 정답이 섞여 있었다(`log.md` 2026-09-27 진단). lang8은 테스트 원문의 28%가 학습셋에 다른 정답으로 들어 있다. 두 요인 모두 점수 상한을 낮추고 모델 간 차이를 줄인다.
- **GPU 구성 혼합**: kanana는 A100 × 2와 H200 × 1을 섞어 썼다. 같은 run의 재개는 같은 구성으로 했고, seed 간 흔들림이 작아(±0.04–0.32) 구성 차이의 영향은 드러나지 않았다. 같은 가중치라도 GPU·batch 구성이 다르면 빔 탐색 결과가 드물게(64문장 중 0–2개) 달라진다.
- **오류 유형별 점수**는 논문 방식의 재구성이다. 재현 KoBART로 검증했지만 원 계산 코드와 같다는 보장은 없다.
